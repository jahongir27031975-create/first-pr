# Мой первый PR

Учебный репозиторий для знакомства с Git и GitHub.

## Как предложить изменение

1. Создайте отдельную ветку: `git switch -c docs/my-change`.
2. Измените README и сохраните файл.
3. Проверьте изменения: `git diff`.
4. Подготовьте файл: `git add README.md`.
5. Сохраните изменение в истории: `git commit -m "docs: improve README"`.
6. Отправьте ветку на GitHub: `git push -u origin docs/my-change`.
7. Откройте pull request (PR): `gh pr create --base main`.

В PR опишите, что изменилось и как вы проверили результат.
После проверки PR можно объединить с основной веткой `main` на GitHub.

## Памятка: основные команды Git

Ветка — отдельная линия работы над проектом. Коммит — сохранённое изменение в истории.
`main` — основная ветка этого проекта, `origin` — имя его удалённой копии на GitHub.

| Команда | Что она делает простыми словами |
| --- | --- |
| `git clone <URL>` | Скачивает репозиторий и его историю в новую папку. Вместо `<URL>` укажите адрес репозитория. |
| `git status` | Показывает текущую ветку и файлы, изменения которых ещё не сохранены в коммите. |
| `git diff` | Показывает изменения, которые ещё не подготовлены командой `git add`. |
| `git diff --staged` | Показывает подготовленные изменения, которые попадут в следующий коммит. |
| `git branch` | Показывает локальные ветки; текущая отмечена звёздочкой. |
| `git switch -c docs/my-change` | Создаёт новую ветку `docs/my-change` и переключается на неё. Выберите свободное имя для новой работы. |
| `git switch main` | Переключает на основную ветку. Перед переключением сохраните текущую работу в коммите. |
| `git add README.md` | Подготавливает текущие изменения README к следующему коммиту. Сам коммит ещё не создаётся. |
| `git commit -m "docs: improve README"` | Сохраняет подготовленные изменения в локальной истории с поясняющим сообщением. |
| `git log --oneline -5` | Показывает пять последних коммитов текущей ветки в кратком виде. |
| `git push -u origin docs/my-change` | Отправляет ветку на GitHub и запоминает, с какой удалённой веткой она связана. |
| `git push` | Отправляет новые локальные коммиты в связанную удалённую ветку. |
| `git pull --ff-only` | Получает изменения из связанной удалённой ветки и обновляет текущую, только если её можно продвинуть без объединения разошедшихся историй. Иначе останавливается. |

Обычный порядок работы: `git status` → `git diff` → `git add README.md` →
`git diff --staged` → `git commit` → `git push`.
Для `git commit` укажите сообщение через `-m`, как в таблице, либо в открывшемся редакторе.

Коммит сохраняет изменения на вашем компьютере; `git push` отправляет их на GitHub.
Открытие PR — отдельный шаг. Команда `gh pr create` из инструкции выше относится к GitHub CLI.

## Частые ошибки новичка и как их исправить

Перед исправлением выполните `git status`: он покажет текущую ветку и состояние файлов.
Команды ниже вводите в терминале из папки учебного проекта.

### Git пишет `not a git repository`

Вы находитесь вне папки репозитория. Например, из папки, содержащей `first-pr`, перейдите в неё:

```powershell
cd ./first-pr
git status
```

Не запускайте `git init` в случайной папке: это создаёт новый репозиторий, а не находит существующий.

### Коммит не создаётся: `nothing to commit` или `no changes added to commit`

Сначала сохраните README в редакторе и выполните `git status`.
Если файл изменён, подготовьте его и проверьте, что попадёт в коммит:

```bash
git add README.md
git diff --staged
git commit -m "docs: update README"
```

Если Git сообщает `working tree clean`, новых изменений для коммита нет.

### Git просит указать имя и почту: `Author identity unknown`

Укажите свои данные для коммитов только в этом репозитории:

```bash
git config user.name "Ваше имя"
git config user.email "ВАША_ПОЧТА"
```

Замените примерные значения своими. Можно использовать адрес `noreply` из настроек почты GitHub.
После этого повторите команду коммита.

### Новая ветка не создаётся: `a branch named ... already exists`

Команда `git switch -c` создаёт новую ветку. Чтобы продолжить работу в существующей,
сначала сохраните текущую работу в коммите, затем используйте `git switch docs/my-change`.
Для новой задачи выберите другое свободное имя: например, `git switch -c docs/another-change`.

### Git не даёт переключить ветку: `Your local changes ... would be overwritten`

Сначала просмотрите `git diff` и `git diff --staged`. Если правки нужны, подготовьте нужные
файлы через `git add` и сохраните их командой `git commit -m "docs: save current work"`.
Затем повторите переключение. Не удаляйте изменения только ради смены ветки.

### При `git push` появляется `has no upstream branch`

Git ещё не знает, с какой веткой на GitHub связать вашу локальную ветку.
Узнайте её имя командой `git branch --show-current`, затем выполните:

```bash
git push -u origin ИМЯ_ВЕТКИ
```

Замените `ИМЯ_ВЕТКИ` фактическим именем текущей ветки. После этого достаточно `git push`.

### Отправка отклонена: `non-fast-forward` или `fetch first`

На GitHub есть коммиты, которых нет у вас. Сохраните текущую работу в коммите,
затем, находясь в нужной ветке со связанной удалённой веткой, выполните:

```bash
git pull --ff-only
```

Если обновление прошло успешно, повторите `git push`.
Если Git сообщает, что истории разошлись и fast-forward невозможен, остановитесь:
потребуется отдельно разобраться с объединением изменений. Не используйте `git push --force`
как обычное исправление — он может перезаписать историю на GitHub.

### GitHub CLI сообщает, что вход не выполнен

Это проблема подключения к GitHub, а не сохранения файлов в Git. Выполните:

```bash
gh auth status
gh auth login --hostname github.com --git-protocol https --web
```

Завершите вход в браузере и повторите действие. Пароль и одноразовые коды вводите только
на странице GitHub; не добавляйте их в README или коммиты.
